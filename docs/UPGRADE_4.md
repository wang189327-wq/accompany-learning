# 升级到4.0

## 用户看到的变化

- 原“任务清单”改“作业清单”，“历史任务”改“作业档案”；原打卡、补交、评分、备注、提醒、排序及小组件保留。
- 新的“任务”是作业的可选归类，只填写名称、学科、学期，不独立打卡、计分或产生周期。
- 先点“+发布任务”建立任务，再发布或修改作业时输入任务名称关键词，从候选中点选。一个作业最多关联一个任务，任务可关联多份作业；双方共享任务选项。
- 原作业全部未关联。选择任务不会覆盖作业自己的学科、学期。任务名允许重复，按稳定ID区分，候选同时显示学科、学期。
- 作业档案的“任务名称”筛选在“作业名称”下方。输入词后需点选；支持“全部任务”“未关联任务”，与原名称、学科、多学期筛选同时生效。
- 卡片、提交、评分、完成记录及趋势表不展示内部轮次编号；未完成项目仍用计划日期区分，提交记录仍显示实际完成时间。补交、颜色、暂停和自动打卡的周期计算不变。

## 后台升级顺序

1. 使用原接口的备份能力做好云端备份，保留原函数代码与环境变量。不删除原任务表、记录表或OSS文件。
2. 按[阿里云部署教程](DEPLOY_ALIYUN.md)构建并上传新的“伴学记录云端接口部署包.zip”到原函数。ZIP根目录应含`server.cjs`、`core.cjs`、`task-service.cjs`、`assignment-groups.cjs`、`assignment-groups.js`及原有依赖。
3. 保留原环境变量、执行角色、OSS和Tablestore，启动配置不变；无需新增表、权限或密钥。
4. 访问原`/health`，确认`build:55`及`features.assignmentGroups:true`。接口协议仍是`1.6.0`，不是安卓显示版本。
5. 上传4.0网页并安装同签名4.0/55 APK。需要App内更新时按[网页与更新教程](DEPLOY_WEB.md)放置对应更新清单和APK。
6. 确认旧作业/图片/评分/点评仍在；发布一个任务，关联一份作业，在另一设备同步和筛选；再检查资料、试卷和“我的”设置。

新前端连接旧后台仍能读取原数据；新增任务和关联需要新后台。未部署时会明确提示，不能静默丢关联。旧前端修改已关联作业时缺省保留关联，明确传空值才解除。

## 数据与回退

新任务目录在既有记录表的独立命名空间`__c9_assignment_groups__ / catalog`中；不会参与作业的自动打卡或完成记录扫描。作业字段`assignmentGroupId`可为空。完整与增量快照都返回整个任务目录。

云端备份包含任务目录。新版本地测试备份格式为2，读取旧格式1时仍兼容；旧客户端不能恢复格式2，避免忽略任务目录。保留业务记录，不执行云端清空。

回退前先备份。旧版不会显示任务关联，但新版后台会保留关联；不要用旧本地备份覆盖已有新关联数据。线上部署与真实设备安装须单独验收，源码检查和浏览器模拟不能代替。
