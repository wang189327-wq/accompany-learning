# 数据结构及不可破坏的规则

下面是关键字段说明，不是完整校验器。默认值、合法取值及兼容处理以三个模型文件和行为测试为准。日期数值均为毫秒时间戳；周期边界按北京时间。

## 任务

```js
{
  id: 'immutable-task-id',       // 技术关联键，改名称不改ID
  name: '阅读练习',
  kind: 'recurring',              // once / recurring
  rule: 'week',                   // day / week / month；单次不使用
  format: 'image',                // text / image / file / auto
  subject: '语文',
  semester: '七年级上学期',
  createdBy: 'teacher',           // teacher / student
  requiresTeaching: false,
  enabled: true,
  revision: 3,                    // 并发写入用，不是软件版本
  created: 1793844000000,
  deadline: null,                 // 单次任务日期
  weekDays: [0, 6],               // 周一0至周日6
  note: '长期任务备注',
  roundNotes: { '2026-W45': '本周备注' },
  pausedRounds: [],
  deletedAt: null
}
```

发布任务仅名称必填，其余字段由模型处理可选值。上例只是示意，不应作为绕过`validateTask`的直接入库模板。

后台额外保存`_rounds`（提交引用）、`_events`（任务消息）。客户端任务通过`visibleTask`去除这些内部字段；不要把客户端传入的内部引用直接当成可信数据。

## 轮次与提交

- 每日：`YYYY-MM-DD`；每月：`YYYY-MM`；每周：ISO周标识`YYYY-Www`；单次：`单次`。
- `round`表示业务轮次，`recordKey`标识具体一次提交。同轮重复补交可能带`~requestId`后缀，不能只按round覆盖。
- `requestId`标识一次提交会话；同一请求重试返回原成果，内容变化不能冒用原请求。
- `completed`和`late`由服务端最终保存时计算，手机自行提交的时间不能覆盖它们。

提交摘要包括`taskId`、提交时的`taskName`、`format`、`round`、`selfScore`、附件引用和完成信息。名称冗余保证删任务后成果仍可查看；作业内容不可编辑，周期补交创建新记录。

## 评分与版本

自评和教师评分为0–10整数。自评在提交时保存；老师评分可之后修改。`gradeRevision`用于评分/摘要的条件写入；任务使用自己的`revision`，不能互换。

评分颜色：8及以上绿，5–7黄，低于5红。自动打卡没有手工评分要求。

## 资料与试卷

`type`为`folder`、`material`或`exam`。文件夹用`scope`区分资料页与试卷页；资料/试卷用`folderId`关联，可为空。`files`保存不可变上传编号及对象引用。

资料和目录的`semesters`可多选。试卷的`semester`为自身学期；试卷只需名称及附件，其余可选，包括`score`、`fullScore`、`targetScore`、班级`rank`、年级`gradeRank`、`examDate`及备注。

趋势按考试填写日期统计；分数按`score / fullScore * 目标分制`换算，排名保留原名次，缺失值不能当0分或第0名。学习目标的满分不限制单次试卷满分。

## 身份、删除和权限

角色是互信双方的界面模式，访问码共享。老师管理双方任务；学生只管理自己任务，但可通过专用接口修改每周完成星期。备注和评分仍各有权限规则。

普通删除任务是软删除，保留成果；老师可查已删任务，学生不可查。停用和暂停轮次不同；默认打卡停用后当天不继续展示为完成，过去日期按原规则保留。

删文件夹不删资料，内容回到根目录。不要在重构时把这些操作改成删除OSS原对象。

## 存储位置

Tablestore两张表主键见部署教程；记录表内还有资料、设置、已读、AI等内部命名空间。原文件和提交内容在OSS。短文字与点评摘要可缓存到记录表，目的是减少重复读取，不改变原成果归属。

`C9_*`环境变量、`c9-*`设备键和包名沿用旧项目标识。显示名称改动不意味着应该迁移这些字段。

## AI请求

点评与具体`recordKey`绑定。按钮点击、云端接受、电脑领取和结果保存是不同状态；只有电脑领取后才显示正在点评。同一提交复用已完成结果，补交独立点评。

电脑已领取后用户退出App不取消任务。回传幂等、待回传恢复和较新结果保护必须保留，失败不能悄悄变成成功或清掉已有点评。
